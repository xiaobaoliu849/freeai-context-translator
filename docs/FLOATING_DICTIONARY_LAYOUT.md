# 划词词典布局修复

本轮修复针对网页内词典窗口信息被裁切、按钮出现浏览器默认粗边框，以及较长词性说明挤占阅读空间的问题。

## 原因与改动

- 浮窗原为 460×590，而内部 App 使用 `h-screen`，按宿主网页的整个视口计算高度。外层 `overflow: hidden` 会裁掉内部底部。现在 App 跟随浮窗实际可用高度，词典正文使用单独的滚动区域。
- Shadow DOM 没有网页入口的 Tailwind preflight。补充仅作用于 `.yumai-app` 的基础重置，并明确 theme/base/components/utilities 层顺序，避免重置覆盖工具类。宿主网页的按钮、文字与边距保持原样。
- 浮窗主题使用像素单位的间距和正文字号，避免宿主网页自定义根字号放大控件。浏览器自身缩放仍然生效。
- 默认窗口为 560×720，可展开至 820×900，实际大小始终受视口减去四周 12px 限制。支持右下角调整大小、拖动标题栏移动，以及窗口变化后的重新定位。
- 单词与操作按钮独立成行；音标、完整词性、CEFR 和不同于当前词的原形另行排列。
- 首先显示句中含义，其后为语境辨析和通用释义。原文语境可展开完整阅读，并标记当前词。搭配、近义表达、反义表达和例句按需展开；内容不被删除或省略。
- 新增扩展 `workspace.html`，工具栏的独立标签页按钮打开真正的阅读工作台。

Linux 默认使用 PATH 中的 `google-chrome`。GitHub PR 和 main 分支 push 的 CI 自动执行该脚本并保存截图。

脚本注入真实构建的 `content.js`，使用真实 Shadow DOM 和真实 React App；仅替换 Chrome 存储及后台桥接为固定公开样例。检查：

- 宿主根字号为 24px、按钮有 5px 边框时，浮窗字号、边距和按钮仍正确，宿主样式不变。
- 390×480、640×360、853×600（1.5 倍显示密度）视口下没有水平溢出，正文底部位于可见窗口内。
- 可以滚动到最后一条例句、完整展开原文、展开或恢复窗口、用原生调整大小手柄改变尺寸、编辑选中文本。

## 翻译弹窗的清晰度

对用户提供的 NextAI 与 YUMAI 空态截图进行界面对比后，进一步简化翻译视图：

- 将工具栏 popup 的原文/译文合为一个连续编辑面，减少大圆角卡片、阴影和重复分隔线。
- 原文提示、译文正文和区域标题使用更深的文字颜色；去掉空态斜体和装饰性闪烁。浏览器检查确认提示与正文对比度至少为 4.5:1。
- 空输入时翻译按钮仍禁用，但用明确的中性背景和可读文字表示状态；不再依靠低透明度。
- 复制和朗读操作仅在有内容时显示。译文操作增加文字标签，界面中只保留一个服务商入口。
- 普通句子不展示多余的模式说明行。桌面比例预设收入“布局”菜单，点击预设后菜单关闭；分隔线仍支持拖动及键盘调整。
- 源语言检测结果尽量显示语言名称，避免只显示代码。

回归脚本同时检查空态、输入后状态、键盘翻译、复制、清空、长原文与长译文的内部滚动、桌面布局预设，以及原有划词浮窗。新增截图为 `preview/yumai-popup-clarity-*.png`，CI 一并保存。

上述对比针对界面；截图没有实际译文，无法据此评价不同模型的翻译质量。浏览器验收使用固定样例响应。

## 对抗性审查

在真实构建的浏览器 UI 中复现并修复以下问题：

- 清空输入时未中断请求，迟到的响应会重新显示已清空的译文。清空与新建文档现在共用状态重置逻辑，先使旧请求失效再中断请求。服务器和客户端降级路径均传递取消信号，取消后不再触发下一层降级调用。
- 剪贴板权限请求晚于文本替换完成时，新文本会错误显示复制成功。复制请求和反馈计时器现在随内容变化失效，旧请求成功或失败都不能更新新内容的反馈。
- 关闭布局菜单后焦点留在隐藏按钮中。选中预设与 Escape 关闭均将焦点移回“布局”。
- 生成期间手动删除全部原文会禁用“停止”。停止按钮现在只在没有任务且输入为空时禁用。

回归测试包括忽略取消的迟到响应、遵守取消的服务器降级请求、延迟剪贴板响应、清空原文后的停止按钮，以及布局菜单焦点与 Escape。上述用例使用模拟响应，不调用真实模型服务。
